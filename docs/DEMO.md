# A deliberately unproductive Chuddy demo

Use the source launcher or the complete packaged folder described in `PACKAGING.md`. The first launch must show a stopped session, microphone off, and simulated/disarmed hardware. No API key or Raspberry Pi is needed to explore the interface.

## Prepare once

1. Run the free local model setup if actual AI decisions are part of the demonstration. In Companion studio, confirm the local model is ready. Preparation alone does not mean a model has answered.
2. Configure a local voice worker and suitable voice reference if available, then deliberately enable voice and listen to a test. An unreviewed voice is an approximation; Windows speech is a generic fallback. Do not claim an accurate match without hearing it.
3. For real sound inference, prepare the optional YAMNet model. Manual and sound-test scoring remain available without it and retain their labels.
4. Optional: run the friends service locally/on the LAN and configure a private room. Install and pair the browser extension only when desired. No worldwide deployment is implied.

## Walkthrough

1. **Meet your supportive friend.** Open Companion. Send “Can you spell report?” and “What is 2 + 2?” Observe the reply's actual source. For the AI demonstration, use a new prompt and confirm the local-model label; scripted troubleshooting output is not fresh AI inference.
2. **Give him context.** Add a fictional report deadline in Deadlines. The displayed due date is real application data; Chuddy's interpretation is the joke. Tell him a harmless preference and inspect any saved local memory in Companion studio.
3. **See real agency.** With the model ready and an opted-in session, observe a disposable matched work window and expand the agent trace afterward. Show the actual requested tool, validation result and resulting behavior. Requests need fresh focused work; asking from the companion alone does not bypass that rule. A failed tool or fallback must remain visible.
4. **Authorize a distraction.** In Work rules, review rules and choose the destination before starting a session deliberately. The test-interruption control is a silent local rehearsal: it does not open a retailer, minimize real work or run a model response. A real accepted game interruption opens and starts the clam game; a casino interruption opens Gary's tables. Retailer choices open only their homepage in Chrome. The inline banner's **Return to work**, Escape and persistent **Stop** remain usable.
5. **Preserve the actual work.** If demonstrating a real work window, use a disposable unsaved test document. Cover or minimize it, then return and verify its text is intact. No editor process should be terminated. Stop before returning to ordinary work.
6. **Press the belly.** Deliberately run the simulator from the companion or studio. Show yaw-only turn and return with spray disabled. Inspect the labeled simulator sound event. A physical Pi demonstration is separate and requires real calibration/enabling.
7. **Achieve a stupid metric.** Open Stupidest metric and use a deliberate sound test or manual event. Point out its source label. Microphone classification needs a separate intentional Start microphone action, visible recording status and later Stop. Chuddy's own sounds may count; silence and synthetic tests do not prove accurate detection.
8. **Earn and lose some pretend clams.** Inspect the earnings source/rate labels after a new score event. Complete a server-ticketed 20-second clam game with at least three accepted self-reported catches to see the eligible fixed reward; daily limits remain visible. In the clam club, choose local slots, blackjack, Texas Hold'em or roulette and inspect the accurate wallet reservation/return. A free pretend deposit and the fictional shop remain available. The security desk only offers preset imaginary answers. There is no bank connection, real checkout or purchase. Portraits or revised artwork marked pending are unfinished assets, even when the underlying game works.
9. **Check persistence.** Stop the session, close and reopen Chuddy, then verify settings, history, deadlines, scores and play balance survived. The restarted session and microphone must remain off.
10. **Optional friends check.** Use two local profiles/clients to sync with the private friends room. Show local/LAN scope and event provenance rather than claiming a public global leaderboard.

## Keep the claims honest

Demonstrate local AI offline only after its required models are installed. Verify a new response and actual permitted tool call; a cached line or filler is not the answer. Report measured cold/warm latency separately, and name the voice engine actually used.

The simulator, generic speech fallback, manual/test events and uncalibrated classifier are useful prototype features with explicit labels. They do not validate physical motion, spray, microphone accuracy, voice similarity or a worldwide service. Real hardware testing is user-operated and outside automated software checks.

Stop the session and microphone at the end. Keep the original concept/reference preserved separately from these demonstration choices.
