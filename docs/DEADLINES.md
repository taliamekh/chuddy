# Automatic deadline subscriptions

Chuddy can refresh Google Calendar and Brightspace through their read-only iCalendar subscription feeds. Connect each source once in Deadlines; individual assignments and events do not need to be typed into Chuddy. Connecting a source is a deliberate user action. The application cannot inherit a Codex or browser account session automatically.

Google: open Calendar → Settings → the calendar under **Settings for my calendars** → **Integrate calendar** → copy **Secret address in iCal format**. Paste it into Chuddy's Google Calendar connection field. School/work administrators can disable this address; Chuddy does not bypass that restriction. See [Google's calendar synchronization instructions](https://support.google.com/calendar/answer/37648).

Brightspace: open **Calendar** → **Settings**, enable calendar feeds if available, then **Subscribe**. Choose **All Calendars and Tasks** to include all published course calendars, and copy the subscription URL into Chuddy's Brightspace connection field. This imports events that the school actually publishes to that feed. Missing instructor dates, unpublished work, or a disabled subscription service cannot be inferred. See [D2L's Calendar subscription instructions](https://community.d2l.com/brightspace/kb/articles/18042-manage-course-events-with-the-calendar-tool).

The private feed URL grants read access and is a secret. Chuddy protects it with Windows DPAPI for the current Windows user, keeps it out of public state and logs, and never sends it to the local language model or friends service. No account password is requested. No calendar events are modified remotely.

After connection, Chuddy refreshes every 15 minutes while the application runs and resumes on the next launch. **Refresh now** requests an immediate update. A successful refresh reconciles stable event identifiers: changes update existing imported rows and deleted/cancelled source events remove their imported rows. A failed fetch or invalid feed preserves the last successful deadlines and shows an error. Disconnecting removes that source's local imported rows and protected link; manual deadlines and other providers remain.

Sources are separate for each local profile. Google event start times and task due times are retained in UTC after interpreting their supplied time zone. Floating times use the calendar's declared time zone, or the connection's IANA time zone (default America/Toronto). All-day events are labelled **[all day]** and retain their original calendar date and time zone separately. Their stored midnight is a date anchor, not an exact clock deadline supplied by the source; the UI should show the original date without a time and judge overdue status by the calendar's date.

The import window is seven days in the past through 366 days ahead and moves on every refresh. Recurrence supports daily, weekly, monthly and yearly rules, exclusions, and moved occurrences, including daylight-saving changes. Very large feeds, malformed data and recurrence more frequent than daily produce an explicit unsupported-feed error instead of a partial import. This is a calendar feed integration, not a full Brightspace assignment API or a Google OAuth sign-in integration.

HTTP fetching uses HTTPS provider feeds, public DNS with an address pinned to each connection, verified TLS, bounded body size, socket timeouts and a bounded redirect count. No proxy credentials, cookies or browsing history are involved. Network access is required to refresh; previously imported deadlines remain local when offline.

Calendar parsing uses the free [icalendar parser](https://icalendar.readthedocs.io/en/latest/) and [recurring-ical-events recurrence implementation](https://recurring-ical-events.readthedocs.io/en/latest/user-guide/examples.html). Required versions are recorded in requirements.txt. The integrations have been exercised with local fixtures and mocked transports; real Google and school feeds still require the user's one-time connection and account-specific acceptance.
